## 🚀 Overview

NexusTrade is a high-performance stock trading web application engineered on a **dual-database architecture (SQL + NoSQL)**:
- **MySQL 8.x (Source of Truth)**: Handles transactional consistency (ACID), accounts, cash balances, portfolios, durable order execution, audit logs, and analytics views.
- **Redis (WSL2 NoSQL Buffer & Cache)**: Ingests trade requests at microsecond latency via **Redis Streams**, caches trade status in **Hashes**, ranks volume via **Sorted Sets**, and routes rejected orders to a **Dead-Letter Stream**.

---

## 🏗️ Advanced Database Concepts Implemented

1. **ACID Transactions & Row-Level Locking (`FOR UPDATE`, Savepoints)**:
   - Row-level locks on `accounts` and `stocks` prevent race conditions and balance discrepancies.
   - Per-event savepoints (`SAVEPOINT event_savepoint`) inside the batch cursor isolate failures without rolling back the entire batch.
2. **Stored Procedures (`execute_trade` & `flush_trade_batch`)**:
   - `execute_trade`: Encapsulates validation, weighted average cost recalculation, and order insertion.
   - `flush_trade_batch`: Implements an explicit SQL cursor iterating over staged Redis events.
3. **Database Triggers (`trg_trade_marks_order_executed` & `trg_trade_audit_insert`)**:
   - Automatically marks parent orders as `EXECUTED`.
   - The second trigger (`FOLLOWS trg_trade_marks_order_executed`) writes immutable records to `trade_audit`.
4. **Relational Views (`vw_account_portfolio` & `vw_stock_trading_summary`)**:
   - Real-time portfolio calculation (market value, weighted cost basis, unrealized P&L).
   - Aggregated trade volumes and total traded value per stock ticker.
5. **NoSQL Database Integration (Redis 8.x in WSL2)**:
   - `trading:trade_requests`: Redis Stream queue for immediate ingest.
   - `trading:trade_rejections`: Dead-letter queue capturing rejected orders with MySQL error diagnostics.
   - `trading:trade_status:<event_id>`: O(1) status hashes (`PENDING`, `PROCESSED`, `REJECTED`).
   - `trading:stock:request_volume`: Sorted Set leaderboard for real-time asset rankings.
   - `trading:trade_analytics`: Atomic counters (`HINCRBY`).

## ⚙️ Quick Start

### 1. Prerequisites
- MySQL 8.x running locally (password: `ashwath` or set in `.env`)
- Redis running in WSL:
  ```bash
  wsl sudo service redis-server start
  # Verify with:
  wsl redis-cli ping  # Returns PONG
  ```

### 2. Configure Environment (`.env`)
Create or edit `.env` in `dbms-project/`:
```env
MYSQL_HOST=127.0.0.1
MYSQL_PORT=3306
MYSQL_USER=root
MYSQL_PASSWORD=ashwath
MYSQL_DATABASE=trading_app
REDIS_URL=redis://127.0.0.1:6379
PORT=3000
```

### 3. Initialize Database Schema
If not already applied, run:
```bash
# In MySQL:
mysql -u root -pashwath trading_app < database/schema.sql
mysql -u root -pashwath trading_app < database/advanced.sql
```

### 4. Install Dependencies & Build
```bash
npm install
npm run build
```

### 5. Launch the Application
```bash
npm start
```

Open your browser at:
👉 **[http://localhost:3000](http://localhost:3000)**
